# ASPlayer 产品设计文档

- **日期**：2026-08-26
- **状态**：已评审定稿（v2，含四项用户修订）
- **许可证**：GPL-3.0
- **定位一句话**：开源的双语字幕播放器——为任何没有字幕的外语音视频**一次生成、永久复用**的双语字幕资产。ASMR 后台收听是切入场景与差异化来源，语言学习是产品天花板。

---

## 1. 项目缘起与竞品结论

作者需求：国外优质 ASMR 资源无字幕，希望自动识别+翻译后舒适收听。调研 LLPlayer 后发现其痛点：退出不保存状态、无中文界面、无迷你窗口、翻译不持久化（每次重翻）、常用操作快捷体验不足。

### 竞品分析结论

| 竞品 | 形态 | 借鉴点 | 不跟随点 |
|---|---|---|---|
| [LLPlayer](https://github.com/umlx5h/LLPlayer) ⭐4k | Windows 桌面播放器（C#/WPF/FlyleafLib） | 字幕轨道思想、显示模式、模型下载器模式（本体不含模型） | 实时架构（我们要离线缓存）、仅 Windows 思维、实时翻译即弃 |
| [asbplayer](https://github.com/asbplayer/asbplayer) ⭐1.4k | 浏览器播放器+扩展 | 自动暂停/循环等学习交互 | Anki 深度集成（非我们受众） |
| [VideoCaptioner](https://github.com/WEIFENG2333/VideoCaptioner) ⭐15.7k | AI 字幕批处理工具 | LLM 断句/纠错/批量翻译的提示词工程 | 非播放器 |
| Language Reactor / Trancy | 商业浏览器插件 | 双语字幕学习场景验证 | 仅限流媒体网站 |

**核心架构洞察**：LLPlayer 的"实时处理"只在在线流媒体场景不可替代；本地文件场景下，**离线批处理 + 结果永久缓存**全面占优（可用大模型慢跑、翻译带全文上下文、二次打开零成本、后台零 GPU 占用）。这同时天然解决 LLPlayer 的"翻译不保存"痛点。

## 2. 目标用户与核心场景

**用户画像**：外语 ASMR 爱好者 + 语言学习者；资源以本地 mp4/H.264 视频和音频文件为主；硬件多样（并非人人有 N 卡）；软件需分发给普通用户（不可要求配环境）。

| 场景 | 频率 | 设计含义 |
|---|---|---|
| 🎮 打游戏时后台听（静音游戏音） | 主场景 | 迷你悬浮字幕窗⭐、全局快捷键⭐、极低资源占用⭐、转写绝不自动跑 |
| 💻 坐电脑前当视频看 | 次场景 | 主窗口完整播放界面 + 歌词式双语字幕面板 |
| 😴 睡前闭眼听 | 明确不做 | 属手机端范畴，超出范围 |

## 5. 播放模式（Playback Profile）

学习相关行为开关打包成可整体切换的模式，而非散落开关：

| 行为 | 🎵 连播模式（全局默认） | 📚 精听模式 |
|---|---|---|
| 自动暂停每句 | ❌ | ✅ |
| 单句循环 | ❌ | 可选 |
| AB 循环 | 手动可用 | 手动可用 |
| 盲听隐藏 | ❌ | 可选（临时切原文/译文态） |

- 状态栏一键切换；快捷键可切
- **按文件/文件夹覆盖**：覆盖值存媒体库元数据，NULL = 跟随全局
- 典型用法：ASMR/音乐用连播，语言教学视频文件夹固定精听

## 6. 技术架构（路线 A：纯 Rust 栈）

选型结论：**Tauri 2 + whisper.cpp（whisper-rs）+ Vue 3**。决定性因素是打游戏主场景的资源占用（对比过 Python sidecar 路线 B 与 Electron 路线 C，均因体积/内存被否）。若将来 whisper.cpp 对某些 ASMR 音频效果不佳，转写引擎适配层预留更换 faster-whisper 的接口。

```
┌─────────────────────────── Tauri 2 应用 ───────────────────────────┐
│  ┌─ 前端 WebView (Vue3 + TS + Pinia) ──┐   ┌─ Rust 核心层 ───────┐ │
│  │ 主窗口：媒体库/播放器/双语面板/设置   │←─▶│ 任务调度器(异步队列, │ │
│  │ 迷你悬浮窗(独立置顶 WebviewWindow)    │IPC│ 断点续跑,可取消)    │ │
│  └──────────────────────────────────────┘   │ 转写引擎适配层       │ │
│                                             │  └─ whisper-rs      │ │
│  首次使用下载 Whisper GGUF 模型              │ 翻译引擎适配层       │ │
│  (进度显示, HF 国内镜像加速)                 │  └─ OpenAI兼容/DeepL│ │
│                                             │ 媒体库管理 / SQLite  │ │
│                                             │ ffmpeg 探测与抽音轨  │ │
│                                             └──────────────────────┘ │
└─────────────────────────────────────────────────────────────────────┘
外部依赖：ffmpeg.exe（GPL 构建，随包附带，与 GPL-3.0 兼容）
```

技术栈明细：
| 层 | 选型 |
|---|---|
| 应用框架 | Tauri 2 |
| 前端 | Vue 3 + TypeScript + Pinia + Vite + vue-i18n |
| 样式 | CSS Variables 主题令牌（三主题的地基） |
| 转写 | whisper-rs（whisper.cpp 绑定），GGUF 模型按需下载 |
| 存储 | SQLite（rusqlite）+ 可选 SRT 伴生文件导出 |
| 全局快捷键 | tauri-plugin-global-shortcut |
| 窗口材质 | window-vibrancy（Mica/Acrylic，主窗口用） |
| 翻译 | reqwest 直调 OpenAI 兼容 API / DeepL |

## 7. 数据模型（SQLite）

```
media_files          媒体库条目
├─ id, path, title
├─ fingerprint       快速指纹：文件大小+首尾64KB哈希+时长（避免整文件SHA-256）
├─ media_type        video / audio
├─ duration_ms, container, has_video
├─ playback_position 上次播放位置
├─ speed, volume     每文件记住的播放参数
├─ profile_override  播放模式覆盖（NULL=跟随全局）
└─ added_at

subtitle_segments    双语字幕（核心资产表）
├─ id, media_id, seq
├─ start_ms, end_ms
├─ text_orig         原文（转写产物或外部字幕导入）
└─ text_trans        译文（NULL=未翻译；逐批回填=天然断点续跑）

tasks                处理任务队列
├─ id, media_id, kind(transcribe|translate|import_subs)
├─ status(queued|running|done|error|canceled)
├─ progress(0-100), engine_params(JSON), error_msg

settings             KV 配置
（全局播放模式、快捷键表、翻译引擎配置、模型选择、主题、界面语言、悬浮窗设置）
```

字幕落盘策略：SQLite 是唯一真源；可选导出 `同名.asplayer.srt` 伴生文件到视频旁——方便用户带走资产，也为二期社区分享（按 fingerprint 匹配复用）埋点。

## 8. 关键流程

### 转写流程
用户手动触发"生成字幕"（绝不自动跑，保护游戏场景资源）→ 任务入队 → ffmpeg 抽音轨为 16kHz WAV → VAD 按静音切块 → whisper.cpp 逐块识别（语言自动检测或手动指定）→ 实时回写 segments 并推送进度 → 可取消，已完成块不重跑。

### 翻译流程
用户选引擎并启动 → 每 20~30 句打包一个请求并携带前后文上下文 → 要求 LLM 返回结构化 JSON → 校验后逐批写入 text_trans → 失败自动重试 → 中断后从最后完成批次继续。

## 9. UI 设计语言："Quiet Glass"（v2 修订版）

> Apple 极简骨架 + 克制的玻璃质感。视觉噪音为零，内容（封面、字幕）是唯一主角。

### 9.1 材质、色彩与排印
- **主题三态**：浅色 / 深色 / 跟随系统（默认）。深色为主推打磨方向，浅色保证同等完成度。**全部颜色必须走 CSS Variables 令牌系统**，禁止写死色值。
- 主窗口：Windows Mica/云母材质打底（window-vibrancy），半透明卡片浮层；弹层用 backdrop-filter 毛玻璃 + 大圆角。
- 色彩：中性灰阶阶梯（深：#0D0D0F → #1C1C1E → #2C2C2E），单一低饱和强调色（暖琥珀/玫瑰金方向），仅用于播放态/进度条/选中态。
- 字体：中文 HarmonyOS Sans / MiSans / 微软雅黑回退，西文 Segoe UI Variable；字幕原文大字中字重，译文小一号次级灰；行高 1.6+，大量留白。
- 动效：Apple Music 歌词式字幕滚动（当前句清晰居中放大，前后句渐隐缩小）；统一缓动 cubic-bezier(0.32, 0.72, 0, 1)，200~350ms。

### 9.2 迷你悬浮窗（招牌功能）
- 独立置顶无边框 WebviewWindow，与主窗口联动但不绑定。
- **纯透明背景（v2 修订）：不做毛玻璃**——模糊会干扰游戏画面。可读性靠白色文字 + 半透明深色描边 + 柔和投影实现。
- 可选"文字底衬"（极淡黑色圆角条）供浅色画面兜底，默认关闭。
- 显示当前句原文+译文，随播放滚动；点击文字跳转该句。
- 鼠标穿透锁定：锁定后点击穿透到游戏，快捷键/托盘解锁。
- 设置项：字号、显示行数(1~3)、字幕显示模式独立记忆、贴边吸附。
- 只显示字幕不做控制按钮，控制全靠全局快捷键；空闲时几乎零 CPU/GPU 占用。

### 9.3 字幕显示模式
字幕面板右上角三态切换器：`[原文] [双语] [译文]`
- 原文模式=沉浸练听力；双语模式=默认（原文大字+译文小字）；译文模式=当故事听。
- **主窗口与迷你悬浮窗各自独立记忆模式**（如游戏中悬浮窗只显译文，学习时主窗口看双语）。
- 与精听模式的盲听功能正交：盲听=临时切原文态的快捷行为。

### 9.4 布局基调与参照
极简顶栏（无边框窗口）/ 窄侧栏媒体库 / 播放区+歌词式双语面板 / 底部播放控制条。
参照系：Apple Music（布局与歌词动效）、macOS 控制中心（毛玻璃层次）、Arc 浏览器（暗色呼吸感）。
实施约定：动手写组件前先产出静态 HTML 高保真原型给用户确认视觉方向。

## 10. 国际化

- vue-i18n 三语言包同步维护：**zh-CN（默认基准）/ zh-TW / en**
- 默认跟随系统语言，可手动覆盖；繁中注意领域词汇习惯用字
- 从第一天接入，杜绝后期国际化的技术债

## 11. 许可与模型分发策略

- **GPL-3.0**：改良必须回馈开源；与 LLPlayer 同协议，可互借代码；ffmpeg 用 GPL 构建无冲突
- **本体不内嵌模型**（沿用 LLPlayer 验证过的模式）：首次使用内置下载器拉取 Whisper GGUF 模型，显示进度，支持 HuggingFace 国内镜像加速；云端 API 选项让无显卡用户完全跳过本地模型
- 开发约定：全程持续参考 GitHub 同类项目实现与踩坑记录（LLPlayer / asbplayer / VideoCaptioner 等）

## 12. 风险与验证计划

| # | 风险 | 验证方式 | Plan B |
|---|---|---|---|
| 1 | Whisper 对耳语/低音量 ASMR 识别率差（最大不确定性） | 里程碑0：最小命令行管线（抽音轨→转写→打印双语结果），用耳语型/正常型/带BGM型真实样本评估 | ffmpeg loudnorm 增益预处理；换更大模型；极端情况转写适配层换 faster-whisper |
| 2 | whisper-rs CUDA/Vulkan 在部分机器不可用 | 启动时硬件探测，列出可用加速档 | 自动回退 CPU |
| 3 | WebView2 视频解码兼容性 | mp4/H.264 已确认可行，收集异常案例 | 二期转码兜底队列 |
| 4 | LLM 翻译长音频的质量与成本 | 真实 ASMR 台词测试提示词 | 调整分批策略；支持 Ollama 本地免费翻译 |

**里程碑 0 通过标准**：真实 ASMR 样本上转写+翻译结果达到"能理解大意"水平，才动手搭 UI。

## 13. 明确不做（防范围膨胀）

手机端、Anki 制卡、词典深度集成、AI 实时同传、在线播放（一期）、毛玻璃悬浮窗。
