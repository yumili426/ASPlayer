# 内置词典（Built-in Dictionary）设计 — MVP 功能

> **状态：设计定稿，待用户审阅后进入实施计划。**

**背景与由来：** 原「查词联动（复制剪贴板 + 自定义浏览器搜索站点）」经可行性讨论被否决，原因：1) 预设的谷歌国内无法访问；2) 跳浏览器链路太长。**改为应用内内置词典**——右键字幕词即在 App 内弹词典卡片，全程不离开 App，离线可用、国内无障碍。本稿替代并升级原「查词联动」MVP 项。

**目标：** 在 App 内对字幕中的词一键查词典，展示发音/词性/释义/例句，离线可用。

**已锁定的决策（与作者逐项确认）：**
- 数据方案：**离线词典**，按需下载（复用模型下载器交互），非打包进安装包。
- 覆盖：**全量**（ECDICT 英汉 + JMdict 日英）。
- 首版语言：**英文 + 日文**。
- 日语释义：**JMdict（日→英）**，先可靠落地；优良日中数据源留作后续扩展。
- 交互：**应用内词典卡片**，不跳浏览器；右键字幕行或行内选中词触发。

**Tech Stack：** Rust（app crate 或新 `asplayer-dict` 纯函数 crate）+ rusqlite（SQLite + FTS5）+ 前端 Vue 卡片组件。复用现有模型下载器基建（download → app_data_dir → 校验 → 解压 → 状态广播）。

---

## §1 数据源与存储

| 语言 | 数据源 | 说明 | 全量体积（SQLite） |
|---|---|---|---|
| 中英 | ECDICT（skywind3000/ECDICT） | 含词频/柯林斯/牛津/词形变化 exchange/双语例句 | ≈30–40 MB |
| 日英 | JMdict（EDRDG，EDICT2） | 辞书形 + 假名读音 + 词性 + 英文释义 | ≈15–30 MB |

- **按需下载**：首次查词时触发，下载到 `app_data_dir/dict/`，进度走现有模型下载器那套 UI/事件。
- **中国访问**：数据源默认走 GitHub；提供可配置镜像/基础 URL（与模型镜像同思路），保证国内可达。
- **一个 SQLite 库**（`dictionary.db`），各语言分表：
  - `en_entries(id, word, phonetic, definition, translation, pos, exchange, freq, detail_json)`
  - `ja_entries(id, surface, reading, pos, gloss, senses_json)`
- **全文索引**：`en_entries` 用 FTS5（unicode61）索引 `word`/`definition`；`ja_entries` 索引 `surface`/`reading`。**CJK 分词是难点**——FTS5 对中文/日文默认按词边界切分不佳，日文读音多为假名/罗马音可直查；中文释义建议用 LIKE/前缀或 FTS5 trigram，具体在计划阶段验证。

## §2 查询引擎（纯函数，重点）

对外输出 `LookupResult { term, phonetic?, pos?, definitions[], senses?, suggestions[] }`。

1. **精确匹配**：`surface`/`word` 相等直接命中。
2. **词形还原**（差异化价值，成败关键）：
   - **英文**：优先用 ECDICT `exchange` 字段反向映射（如 `p:ran`、`d:run`、`i:running`、`3:runs` → 基准词）；命中失败再走规则（去 `-s/-ing/-ed`、`-ies/-ied`、不规则词表）。
   - **日文**：内嵌一套日文活用还原规则，把「食べています / 食べた / 食べて」还成辞书形「食べる」；按表面形与假名读音双重匹配。
3. **相似词建议**：FTS5 前缀 + 编辑距离排序；未命中时返回「你是不是想找…」候选。
4. **语言判定**：按字符集（片假名/平假名 → 日文；拉丁字母 → 英文）决定查哪张表；也支持字幕行的原文语言提示。

## §3 数据流

1. 用户右键字幕行（或行内选中词）→ 前端 `dict_lookup(term)`。
2. Rust：确保词典已下载（未下载 → 返回「未就绪」，前端提示下载并展示进度）；归一化表层词 → 按语言查表 → 词形还原 → 返回 `LookupResult`。
3. 前端渲染词典卡片（发音/读音 + 词性 + 释义/例句；日本语附英文 gloss）。未命中显示相似词建议。

## §4 UI（词典卡片 + 下载）

- **词典卡片**：区域角落浮卡，或在字幕词旁锚定。字段：term、音标/假名、词性、释义（可折叠例句）、未命中时的建议列表；卡片可 Esc/点击外部关闭。
- **下载交互**：首次查词若有词典，进度实时；否则提示「下载词典 (约 50–70 MB)」，带进度条与取消。
- **设置页**：新增「词典」区块/页——显示各语言下载状态、体积、进度、语言开关（英/日）、镜像地址。

## §5 与既有功能的边界

- **不是翻译引擎**：既有「翻译」管线是句级（云端 API，中文输出）；词典是**词级**离线解释。两者并存、不混用。
- **非目标**：不做 OCR、不做句级释意、不在 v1 做 Anki 导出（留作后续）。
- 卡片仅查询，不影响字幕面板既有的跳转/搜索/译文切换。

## §6 测试

- 查询/还原函数放纯函数 crate，无 tauri 依赖，可单测：
  - 英文还原用例：`running→run`、`better→good`、`studies→study`、`went→go`。
  - 日文还原用例：`食べています→食べる`、`食べた→食べる`、`行って→行く`。
  - 精确/FTS/相似建议、语言判定。
- DB 下载解压、校验、镜像 URL 的集成测试。

## §7 计划阶段需验证的点

- ECDICT / JMdict 的准确下载 URL、lib/版本、预打包 SQLite 还是源文件（CSV/XML）转建。
- FTS5 对日文/中文释义的正确检索方案（unicode61 / trigram / LIKE）。
- 词典卡片定位与 CaptionPanel（歌词浮层）联动——是否也要支持在歌词上查词。
- 下载体积与「精简核 vs 全量」在确切数据确认后再核对一次（作者已定覆盖优先）。
