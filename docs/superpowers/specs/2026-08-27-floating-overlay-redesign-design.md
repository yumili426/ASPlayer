# 悬浮字幕窗重设计（桌面歌词化）设计文档

- **日期**：2026-08-27
- **状态**：已与用户逐节评审通过
- **范围**：M3 迷你悬浮字幕窗的问题修复 + 交互/视觉重做（对应设计文档 §9.2 的落地修正）
- **关联**：[主设计文档](../specs/2026-08-26-asplayer-design.md) · [悬浮窗原型记录](../../../.superpowers/)（本地，不入库）

## 0. 背景与要解决的问题

M3 上线后用户反馈四个问题：

1. **无法拖动**：现有拖拽把手是 hover 才浮现的 36×13px 点阵，可抓取面积几乎为零，且文字区被"点击跳转"占用
2. **形态不像桌面歌词**：期望做成网易云 PC 桌面歌词式的悬浮层
3. **显示模式不可切换**：只有双语展示，无原文/译文单语入口（且 §9.3 要求悬浮窗模式独立记忆）
4. **Bug：seek 后冻结**：正常播放字幕正常；一旦在字幕面板点句跳转或快进，悬浮窗停止更新

### 竞品调研结论

网易云/QQ 音乐等桌面歌词通行模式：宽幅半透明歌词条、悬停浮现工具栏（切句控制、歌词偏移、设置、锁定、关闭）、整条可拖拽、锁定=整窗鼠标穿透（解锁靠快捷键或回主窗）。技术映射到 Tauri v2：`transparent + always_on_top` 窗口、手动 `startDragging()` 拖拽、`set_ignore_cursor_events` 穿透锁定——后两者现有实现已具备，问题只在交互面太小。

## 1. 用户决策记录（头脑风暴确认）

| 决策点 | 结论 |
|---|---|
| 视觉方向 | 网易云双行横条的**结构** × Quiet Glass 深色毛玻璃**质感** |
| 译文行颜色 | 设置内提供预设色板自选（默认柔白） |
| 句间空隙行为 | 默认保留上一句；设置可选"5 秒后淡出" |
| 点歌词跳转 vs 整条拖拽 | **移除点击跳转，整条卡片纯拖拽** |
| 增强项范围 | 仅加"悬浮窗独立字号"；±0.5s 歌词偏移 / 贴边吸附 / 行数设置本轮不做（数据结构预留扩展） |

## 2. UI 与交互设计

窗口创建参数不变（floating.rs：560×148、置顶、透明、无边框、skip_taskbar），内部重建：

- **玻璃条**：圆角 18px，底色 `rgba(12,14,20,0.55)` + `backdrop-filter: blur(16px) saturate(130%)`，8% 白描边，柔和投影。WebView2 透明窗上毛玻璃若不生效则降级为纯半透明深底
- **文字**：原文行白色大字中字重；译文行按所选预设色小一号；描边+投影保证游戏画面可读性（§9.2）
- **句切换动效**：150~180ms 淡入淡出；不做歌词位移滚动
- **空态**：保留"开始播放后此处显示字幕"提示

**整条拖拽**：玻璃卡任意位置 `pointerdown` 即调 `startDragging()`；锁定态除外。

**悬停工具栏**（进入玻璃条淡入，移出 2000ms 后隐藏）：

```
⏮句  ⏯  ⏭句   │   [原文|双语|译文]   │   ⚙  🔒  ✕
```

- ⏮⏯⏭：上/下一句、播放暂停 → 经后端中继转发主窗执行（复用 `overlay://step-subtitle` 与 `overlay://global-action` 既有通道，新增对应 Rust command 供悬浮窗调用）
- 三态分段控件：即时切换本窗 display_mode（独立记忆）
- ⚙：就地弹出迷你面板——译文色 swatches（6 色）、句间空隙行为开关、字号滑杆
- 🔒 锁定 / ✕ 关闭

**锁定态**：沿用 `set_ignore_cursor_events(true)` 整窗穿透；此时工具栏不可达，**解锁唯一入口 = 全局快捷键 Ctrl+Alt+L**；主窗工具栏图标同步锁定状态（现有机制）。

**清理**：删除 `overlay_request_seek` 命令、`overlay://do-seek` 监听及悬浮窗文字上的跳转交互样式。

## 3. 偏好设置与同步

新增 `overlayPrefs`，与主窗 captionStyle 完全独立（§9.3 两窗各自记忆）：

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| display_mode | original / bilingual / translation | bilingual | 解决问题 3 |
| trans_color | soft-white / amber / rose / mist-blue / mint / lavender 枚举 | soft-white | 译文行颜色 |
| gap_behavior | keep-last / fade-5s | keep-last | 句间空隙行为 |
| font_scale | f64 0.8 ~ 2.0 | 1.0 | 悬浮窗独立字号 |

存储于后端 settings KV 表（键前缀 `asplayer.overlay.*`，复用 db.rs 现有机制）：

1. 新命令 `get_overlay_prefs()`（返回结构体）与 `set_overlay_prefs(patch)`（写库）
2. 写库成功后 Rust `emit` `overlay://prefs-changed` 同时广播悬浮窗与主窗
3. 悬浮窗启动读取一次 + 监听事件保持响应式；⚙面板修改即时生效并持久化
4. 读取失败一律回落默认值；invoke 失败静默容错（不阻断播放）

## 4. 数据流与 Bug #4 修复架构（方案一：强化推送链路）

新增主窗模块 `overlayFeed.ts`，唯一负责"算该显示哪句并推送"，取代 App.vue 内散落的推送逻辑：

```
时间源（三重保险）                    计算与推送
┌ timeupdate 事件 ─────────┐
│ seeked 事件（关键新增）   │──▶ 读 el.currentTime ──▶ 定位当前句
│ 播放中 500ms 轮询兜底     │      （含 seeking 态处理）    │
└──────────────────────────┘                              ▼
                                        内容级去重：与上次已推送的
                                        文本+start_ms 全等比较
                                                     │ 有变化才推
                                                     ▼
                                 push_overlay_subtitle → 后端中继 → 悬浮窗
```

关键约定：

1. **`seeking/seeked` 事件接入**（现状完全缺失）：任何来源的跳转完成后强制重算重推——seek 卡死的结构性解法。PlayerStage 补挂这两个事件并通知 overlayFeed
2. **内容级去重取代序号去重**：废除 `lastSentOrdinal`，任何异常路径下序号错乱都不再导致永久静默
3. **500ms 轮询兜底**：播放中定时直读 media 元素时间，事件全失效也能自愈
4. **诊断先行**：实施第一步先在旧链路加临时日志复现卡死场景，确认原始触发点后再动刀；根因结论写入提交说明（静态阅读未能 100% 锁定，需运行时证据）
5. **句间空隙执行**：keep-last 空隙期不动（保留上句）；fade-5s 进入空隙满 5 秒推送空 payload 使悬浮窗淡出，下一句浮现时恢复。换文件/无内容/转写中都要清屏
6. **显示模式在悬浮窗本地渲染**：主窗恒推"原文+译文"全量，三态取舍由悬浮窗按自身 display_mode 决定——切模式零延迟零通信；某句缺译文时译文位回退显示原文，绝不空白

## 6. 测试与验收

手动清单（应用无前端自动化测试设施）：

1. 整条拖拽顺滑；锁定穿透正常、Ctrl+Alt+L 解锁有效
2. 三态模式即时生效；两窗模式互不影响；重启各自记忆保持
3. **seek 四连测**：字幕面板点句 / 进度条拖动 / ±15s / 上下句快捷键——每次之后悬浮窗立即显示目标句
4. gap 两行为符合预期；换文件清屏
5. 色板与字号即时生效且持久化；⏯⏮⏭ 主窗失焦时仍生效
6. 回归：显隐切换、锁定快捷键、转写/翻译进度推送不受影响
7. `cargo check` 与 `vue-tsc --noEmit` 通过
8. Bug #4 根因诊断结论写入提交说明

验收标准 = 开篇四个问题在真实使用场景下全部消失。

## 7. 风险与预案

| 风险 | 预案 |
|---|---|
| WebView2 透明窗 backdrop-filter 不生效 | 降级纯半透明深底（观感相近） |
| 自定义命令 ACL 漏配静默失败 | capabilities 逐一核对 + 手动触发验证 |
| Bug #4 根因复杂超出预期 | 三重保险已保证修复效果；若诊断发现更深层的窗口事件缺陷，另行立项处理 |
